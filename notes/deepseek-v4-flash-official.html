DeepSeek V4 Flash Is Official: What the 0731 Build Actually Changes

DeepSeek promoted V4-Flash from preview to production-candidate on July 31. The model you call with deepseek-v4-flash now points to the 0731 build — same 284B-parameter CSA+HCA backbone with 13B activated, re-post-trained for agentic tasks, not rebuilt from scratch.

What you get

The 0731 checkpoint beats V4-Pro preview on all nine agentic benchmarks DeepSeek publishes. That matters less for raw capability than it does for cost: Flash costs a fraction of Pro and uses 4× fewer activated parameters. If your pipeline runs agents, evals, or long-context work, Flash is now the default — not a compromise.

The economics that matter

Below the headline, the real story is caching. V4-Flash hits 98% cache-hit rates on repeated agent pipelines — think multi-turn conversations, cron-driven evals, batch scoring tasks. At that rate, your marginal cost per request drops to near-zero. DeepSeek's pricing page already assumes you'll cache aggressively, and the response-time improvement (sub-second hits vs several-second misses) compounds across 50+ calls per session.

What else shipped

  • Responses API — native structured-output mode, no JSON schema gymnastics
  • Codex integration — straight-through code execution without a separate sandbox wrapper
  • MIT open weights — same day as the API promotion, on Hugging Face
  • DSpark — speculative-decoding module attached to the API endpoint; on-prem serve requires manual setup

Should you migrate now?

If you already target deepseek-v4-flash, you migrated on July 31 without noticing — the API endpoint switched silently. If you held back on V4-Pro waiting for the "real" model, this is it. The only reason to wait for Pro proper is if you need the full 49B active parameters for a task that genuinely can't fit in 13B (rare outside domain-specific RAG at high recall thresholds).
