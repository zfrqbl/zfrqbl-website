A Retrieval Index Is Not Redacted Data

A retrieval index is not redacted data

A visual document retriever reads a page as an image. A vision-language model cuts it into patches of 32 by 32 pixels and returns one vector for each, so a single page becomes an index of about a thousand vectors. A query is scored against the patches that match it, which is why these retrievers sit at the top of the current document benchmarks.

That index then lives in a vector database, often one run by somebody else. Since nobody can read a page out of a list of floats, the index gets filed as the safe copy. The page stayed home, and only an opaque digest went to the vendor.

A paper on arXiv from 7 October 2026 says the reasoning is wrong, and then demonstrates it. Whoever runs or breaches the store can reproduce the page from the index alone.

What the attack assumes

The attacker starts with nothing but the stored index. No source page, no page dimensions, no metadata, no idea which encoder produced the vectors. The paper calls everything else side information and requires zero of it.

Inversion is framed as conditional image generation. A flow-matching model, the architecture family behind current text-to-image systems, is trained on public pages paired with their indices. The index is the condition and the page is the output. A regression model would blur the result, because the best least-squares answer to an ambiguous glyph is an average of the possibilities, so the model has to sample instead of fit.

Everything else the attack needs it works out from the vectors. The encoder is identified by encoding 2,000 reference pages with each public candidate and keeping the one whose vectors best match the store. Across a pool of 13 public multi-vector retrievers, using the index of a single page, it identifies the right one in all 26,000 decisions.

The page shape comes next. A raw index lists its vectors in raster order, so the page width is a period of the sequence. Two vectors one row apart cover patches in the same column of adjacent rows and tend to be similar. Scoring similarity at each lag recovers the shape of 99.2 percent of raw indices.

Then the page is drawn.

What comes back

The model was trained on about 683,000 public pages and evaluated on the 19,252 pages of ViDoRe v3, a professional document benchmark in eight domains. The two sets do not overlap. Eight of the 2,000 evaluation pages have a near-identical training counterpart, and removing them changes no reported number.

From a raw index, the inverted page recovers 47 percent of the words and 45 percent of the sensitive tokens, where sensitive means numbers, capitalised words and acronyms. Used as a query against the whole store, it ranks its own source page first 98.4 percent of the time. An encoder that had no part in producing the index still ranks the source first 97.7 percent of the time, so the match is not an artefact of the encoder that made the vectors.

The controls make the result. An inverter sampled without the index recovers 0.1 percent of the words, so the text is not the model's imagination. A nearest-neighbour baseline, which answers with the closest training page, already recovers 23.4 percent of the words because pages of the same kind share vocabulary. The attack beats that baseline in every domain and beats it on sensitive tokens by 30 points. A recovered financial table comes back with 59 of its 60 numeric cells exact.

Word recall also understates the leak. OCR transcribes only glyphs that formed cleanly, and 75 percent of the pages scoring below 0.1 on word recall still ranked their source page first. The two measures correlate weakly, so a page can be unrecognisable to a reader and still match its source exactly.

Two cheap protections, and one that fails

The paper tests what a store could do about it. Hierarchical token pooling merges the patch vectors, shrinking the index by a factor of three or nine. Shuffling keeps the same vectors in a random order, which costs nothing because late-interaction scoring does not depend on order.

Both cut word recall to about 8 percent, below the nearest-neighbour baseline. Pooling holds. The attack cannot invert a pooled index at all.

Shuffling does not hold. Each vector was computed by a model that saw its patch in the context of the whole page, so it still carries where it belongs. The authors train a position model that reads the shuffled set and predicts each vector's row and column, placing them within 1.8 rows and 4.5 columns on average, against 12.6 and 11.3 for a random order. Handed the restored order, the same inverter re-identifies 93.5 percent of pages, against 98.4 percent from the raw index. Word recall returns to 23 percent.

The restored pages are not clean. Words come back, but whole lines land at the wrong height, so reading the transcript in order gives a scrambled page. Identity survives better than content, because matching a page needs less precision than reading it. That the content follows the vector at all is the finding. Each vector carries its own patch, and the inverter draws the patch wherever the vector is placed.

A second retriever, and what did not generalise

The same attack was then run unchanged against a different retriever from a different group and a different backbone. From the raw index, 70.2 percent of inverted pages rank their source first, against 15.4 percent for the baseline. The dependence on order is the same. Shuffling drops it to 0.6 percent, and the position model only brings it back to 11 percent.

Content did not carry over as cleanly. Word recall stayed below the baseline here, at 7.9 percent. The authors could not isolate the cause, because input resolution, training data and vector count all differ between the two encoders. They also show the gap is not the attacker's data. An inverter for the first encoder, trained on the same smaller corpus, recovered 55.5 percent of the words, more than the main inverter did. They call the reported leakage a lower bound.

What to take from it

The index is the document. If page images go to a third-party vector store, the pages went with them, and a breach of the store is a breach of the content. The paper's own conclusion is that a multi-vector index should be protected like the documents it encodes.

Shuffling is not a protection. It is free to apply and it looks like one, but a small model undoes it, which leaves a store that reads as protected while remaining invertible. Pooling is the defence that held in this evaluation, and it is a real trade. Fewer vectors, a smaller index, and an attack that cannot reconstruct a page from it.

If you are auditing a retrieval store for leakage, the useful test is not whether the inverted page is readable. It is whether it can be matched back to its source, because a page OCR cannot read can still rank its source first.
