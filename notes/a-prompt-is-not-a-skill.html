A Prompt Is Not a Skill

The list that stopped being a list

f/awesome-chatgpt-prompts used to be a readme. You opened it, you copied a prompt, you closed it. Today it is prompts.chat: a website, a command line tool, a Claude Code plugin, a self-hostable server, a 29 chapter book translated into 17 languages, a kids course, and an MCP-first API. The repository still sits well past 140,000 stars. The readme turned into a platform and the old name made most people miss it.

The numbers still say role-play

The library holds 2,744 prompts. Of those, 2,367 are plain text, 356 are structured output in JSON or YAML, and 21 are image prompts. Only 204 are flagged for developers; the rest are general use. The bulk of the collection is the classic 2023-era menu: act as a Linux terminal, act as an Ethereum developer, act as an English translator. That content is fine, and it is also a museum exhibit. The part of the project that is actually moving stopped being the prompts.

The platform arrived underneath

The newest surfaces are growing while the prompt data sits still. The API is MCP-first: the same endpoint answers MCP clients and plain REST calls, so any agent can list prompts, search by keyword, category or tag, and fetch one with its template variables substituted. Search returns title, description, content, author, category, tags and vote count; a prompt with a ${variable} in it is served with the variable elicitation built into the protocol. The whole thing is public, free and rate-limited only by politeness. None of this existed when the repository was a readme.

The read-only tools are the least interesting part of the surface. The revealing ones are save_prompt, improve_prompt and save_skill, where a skill is a multi-file object with a SKILL.md and companion files, not a paragraph. A library that lets you save a skill and search it on demand has crossed a line: it is now a registry, not a list. Self-hosting is a documented option for organizations that want the same surface with complete privacy, which is the same offer every platform makes once it has a distribution problem instead of a content problem.

A prompt is not a skill

A prompt is prose with a goal. It depends on the reader to know what to do with it, to hold the context, to remember the constraints, to format the output. A skill is a file tree: instructions, references, scripts, an explicit shape an agent can load and follow. Same words, different unit. The library's own numbers admit the gap: only about seven percent of prompts are flagged for developer or agent use, and almost none describe agent workflows. Everyone was writing the museum; almost nobody was writing the machinery. So the platform added the machinery, as skills, as MCP tools, as plugins. The message from the maintainers could not be clearer: the prompt text is the commodity, and the executable shape is the product.

Why the unit changed

Because prose does not compose. You cannot version a paragraph, search it reliably, resolve it by name from a tool, or let an agent pull it on demand, unless the interface understands structure. The moment the collection got an MCP endpoint, prompts stopped being artifacts you copy and became records you query. That is the same transition package managers made decades ago: an artifact is only useful when a tool can fetch it deterministically. A skill also has an observable contract. Does the agent do the thing, given the file tree and the trigger, with the references it needs? The observable behavior of a raw prompt is a vibe; you cannot test a vibe in CI.

What a builder does about it

Three moves, in order. First, wire the library in read-only. It is one MCP server entry, no API key for search, reversible in a minute; we connected it to Hermes the same week this note was published. Second, contribute at the layer that composes: original skills and structured-output prompts, not more role-play text. Third, treat your own operating experience as the material. Agent workflows are the visible gap in this library, the same way they were the gap in every tool built before agents existed. The things a working agent runs daily, inbox triage, scheduled scanning, review-before-publish, backup, are publishable knowledge the moment you package them as a skill with a trigger and a contract. That is a contribution with an interface, and contributions with interfaces are the only ones that compound.

The museum keeps the archive, the platform moves

The 2023 readme is still there, and it is still worth a visit as a time capsule. But the project that outgrew it is the actual lesson: the collection was worth less than the interface built around it. The book and the kids course are the same story in another medium: the same knowledge, packaged for a reader who will never open GitHub, distributed in 17 languages. Every packaging step took the material further from the raw list and closer to something someone can actually use. The book ships in 17 languages, including Arabic and Persian, and Urdu is not among them. The gaps are visible and public, which is exactly what makes them opportunities. When your content becomes a commodity you do not defend the content; you build the shape that makes it executable. Prompts.chat stopped being a list the day it became a query, and every prompt library that does not follow will keep being a readme.
